The problem RAG solves

Closed-book exam vs. open-book exam.

Closed-book — a normal LLM

Only knows what it memorized during training. Asked about something outside that, it guesses — sometimes confidently, even when wrong.

Open-book — RAG

Handed the exact relevant pages before answering. Can still get it wrong, but now it's reading real material instead of guessing from memory.

Why RAG, precisely

Four real reasons — not just one.

1. Missing entirely

Too recent, or was never public in the first place. Not a memory problem — there's no memory to draw on at all.

e.g. this morning's product update, or your company's internal API docs

2. Prevents wrong blending

The model may have related but generic memory, and could mix it in unless explicitly told not to.

e.g. generic "connection pooling" knowledge blending with your specific setup

3. Precision over approximation

Training compresses knowledge lossily. Retrieval hands over the exact source text instead of a fuzzy memory of it.

e.g. an exact version number or policy wording, not a paraphrase

4. Traceability

A bonus, not a core reason — but a real one. You can point to which document an answer came from.

e.g. showing the user the exact paragraph the answer was built from

Two ways to give a model new knowledge

Retrain the model, or just look things up.

Fine-tuning

Retrain the model on your data. Real, but slow and expensive — redo it every time your data changes.

RAG

Leave the model alone. Fetch relevant facts at question-time instead. Updates instantly whenever your documents change.

First, the name itself

R-A-G: three words, one pipeline.

R — Retrieval

Go find the relevant material. This is Embeddings and Vector Databases — turning meaning into numbers, then searching them fast.

A — Augmented

Hand that material to the model — added directly into the prompt, alongside the original question.

G — Generation

The model reads what it was given and writes the actual answer, in plain English.

Three words, in order — the name is describing the pipeline itself, not naming some clever trick.

A common assumption, worth correcting early

"We added real documents, so it can't make things up anymore."

Not quite — two separate things have to go right, not one:

1. Retrieval finds the right documents
This can fail — it's the vector search from Vector Databases, and it isn't perfect.
2. The prompt says what to do if they don't
Easy to skip — and if you do, the model guesses instead of admitting it doesn't know.

Skip either one, and you get a fluent, confident, wrong answer instead of an honest "I don't know." We're about to watch this happen live.

Step 3 — the one new idea

One sentence doing all the work.

const context = (results.rows()[0] ?? [])
  .map((row) => row.document)
  .join("\n\n");

const systemPrompt = `Answer using ONLY the following context. If the answer is not in the context, say "I don't have enough information to answer that" — do not guess.\n\nContext:\n${context}`;

That one instruction is doing more work than almost anything else in this system.

A real, fluent answer — grounded in what we retrieved.

const ai = createGeminiClient();
const answer = await generateAnswer(ai, systemPrompt, QUERY_TEXT);

console.log("Grounded answer:");
console.log(`   ${answer.trim()}`);

Every fact in that answer traces back to a document we retrieved a moment ago.

Upgrade 1 — fix the question before searching

Query Rewriting.

Real questions are messy — typos, missing context, ambiguous phrasing. Ask an LLM to clean it up before it ever reaches the vector DB.

const REWRITE_PROMPT =
  "Rewrite the user's question to be clearer and more specific for a search engine. Return ONLY the rewritten question.";

const rewritten = (
  await generateAnswer(ai, REWRITE_PROMPT, QUERY_TEXT)
).trim();

console.log(`Original query:  "${QUERY_TEXT}"`);
console.log(`Rewritten query: "${rewritten}"`);
Upgrade 2 — fix the results before generating

Reranking.

Retrieve more candidates than you need, cheaply. Then have a second pass reorder them by true relevance before they reach the final prompt.

const results = await collection.query({
  queryTexts: [QUERY_TEXT],
  nResults: N_CANDIDATES, // 10 — cast a wide net
});

const candidates = results.rows()[0] ?? [];

const numbered = candidates
  .map((row, i) => `${i + 1}. ${row.document}`)
  .join("\n");

const ranking = await generateAnswer(
  ai,
  RERANK_PROMPT,
  `Question: ${QUERY_TEXT}\n\nPassages:\n${numbered}`
);

The real script also parses this response defensively — Gemini sometimes replies as its own numbered list instead of bare numbers — and falls back to vector order if that fails. Omitted here to keep the slide readable.
